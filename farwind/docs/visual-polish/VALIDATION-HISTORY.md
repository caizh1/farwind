# 验证过程中的问题与处理

以下失败均保留首因，不将失败伪报为通过。

- 旧水纹诊断脚本首次对几十万个alpha值使用展开参数求最值，触发 `RangeError: Maximum call stack size exceeded`。改为归约计算，诊断已完整输出；与游戏运行无关。
- 首次截图导入未处理浏览器确认框，导入被默认取消，界面仍为标题，等待运行模式超时。增加确认框处理；随后局部裁切高度越过截图底边，改为实际可见495世界像素。修改前正式基线仅在站位验证通过后生成。
- 修改后截图曾在同一工作区的热更新期间被重置站位，触发“固定站位不可用”；没有接受这张图为完成证据。后续服务关闭文件监视/热更新，使用独立5181端口。
- 新验收脚本最初只匹配 `/src/main.ts`，遗漏Vite带时间戳的查询字符串，测试实例未注入。改为匹配查询字符串；注入仅用于读取资源及执行Phaser场景重启，不修改游戏状态。
- Phaser使用XHR转blob加载PNG，不能从图片的blob地址检查源路径。验收改为把实际加载图与正式PNG逐像素对比，同时核对纹理key、位置、锚点和显示尺寸。
- 默认Playwright结果目录同时被其他运行清理，曾出现trace的 `ENOENT`；共享热更新服务中出现页面刷新中 `window.__farwind is not a function`。这轮结果为4失败、2通过，不视为有效回归通过。专项改用独立服务、结果目录；原测试断言未修改。
- 南桥北端负向阻挡测试后，玩家位于桥的准确边界。既有导航工具对路径中点要求6像素安全余量，此起点不满足余量，因而无法规划下一段；实际目标站位及其九个余量点均不阻挡。负向断言保持，增加真实向南退回桥面的输入后再导航。
- 暂停检查原先使用固定100毫秒等待，可能在暂停键尚未处理时采样涟漪；改为先确认界面模式确为暂停，再比较450毫秒内水效状态不变。
- 场景重启后全场对象总数减少3，原有按需绘制的战斗Graphics不在本任务新增资源范围。资源验收检查对象总数不增长，并严格要求地表28块、纹理数量、水效2个以及resize监听数量一致，不要求无关临时对象总数精确相等。

在本次首次完整静态接入时，类型检查、76项单元测试及构建全部通过。后续工作区有其他任务正在写战斗/格挡代码；一次类型检查出现 `parryVisual` / `parryWeapon` 未导出、`practice` 不属于Actions，以及 `selectPractice` / `advanceBattle` / `resolveBattle` / `battleFacing` / `drawParry` / `drawWarnings` 尚未定义。此处只记录，不覆盖或修补其他任务中的半成品。

后续并行任务完成相关源码后，类型检查与构建恢复通过。一次全库单测有79通过、5失败：敌人前摇预期0.65但返回650（时钟量纲变化）、旧布尔攻击返回值变为结构化接触对象，以及三项敌人导航/回家旧测试差异；本任务未修改这些测试或战斗代码。后续由实际当前源码与测试重新执行，最终84/84通过。两轮本专项均2/2通过（最新源码再验通过），独立服务上的六项原有动画/会话/地图回归6/6通过，均未开启重试。
