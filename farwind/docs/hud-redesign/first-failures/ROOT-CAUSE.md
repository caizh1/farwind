# 首轮失败与根因

1. 折叠用例：定位器一次匹配两个正文，违反单元素断言规则；两个节点实际均为隐藏。改为分别断言。
2. 导航用例：Tab事件先进入帧输入队列，立即读取仍为游戏态；失败截图已显示行囊。改为等待可观察状态，不重试掩盖原因。
3. 小地图真实缺陷：先以0.6绘制底色，再以0.6叠加遗迹区域，重叠alpha变为0.84，实测214/255。修复为先合成全部地形，再统一遮罩至0.6；道路、桥、水域与玩家标记保持不透明。完整地图不套遮罩。

保存首次失败的截图与追踪，目录均使用英文名称。

4. 折叠后移动测试使用固定180毫秒墙钟。在同时运行截图与软件GPU回归时，模拟只推进少量帧，位置未达到10像素阈值。独立读出确认输入enabled为true、按住d、移动轴为1、动画walk，且位置正常增加；未发现折叠暂停。将用例改为按住直到实际位移满足条件，再松开，遵循现有导航测试的观测式等待。未据此宣称设备性能通过。
5. 首轮全视口截图在源码保存触发Vite热重载时中断，暂停节点随导航被移除。停止编辑源码后重新执行采集；与产品折叠逻辑无关。

6. 旧会话用例在共享机器同时运行三个其他软件GPU浏览器任务时，墙钟400毫秒不足以完成采集动画；截图/诊断仍为attack，产品未发生模式或输入异常。等待真实idle代替固定睡眠。奔跑用例每次切换均已满足模拟时间间隔大于800毫秒，但墙钟测试总时长不同导致19次超过固定18次；总次数上界改以实际模拟时长计算，保留所有切换间隔、体力与恢复断言。

7. 奔跑速度断言在输入开始的第一个采样帧读取到97.916，而非稳定的150；时间轴把该帧的输入时点与模拟步分开处理。改为按住并等待实际速度达到150后记录，后续体力耗尽、恢复、每次切换间隔和按实际模拟时长计算的切换上界仍完整检查；未据此修改产品奔跑参数。
