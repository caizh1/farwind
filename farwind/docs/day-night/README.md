# 昼夜系统

世界只保存累计游戏分钟。新游戏第1日08:00开始；1秒有效模拟时间推进1.5分钟，一日16分钟。菜单、对话、失焦、隐藏、命中停顿沿用原时间轴暂停语义；没有离线推进。

| 时段 | 区间 |
|---|---|
| 黎明 | 06:00—08:00 |
| 白天 | 08:00—17:00 |
| 黄昏 | 17:00—19:00 |
| 夜晚 | 19:00—次日06:00 |

阶段为左闭右开；画面和环境音连续插值。HUD显示日期、钟点和阶段。设置中的夜间可见度只减轻遮罩，最多28%，不会改变时间、感知或战斗。

第一夜安静。后续黄昏生成单条固定计划；20:00—24:00内仍满足原驻防保护、冷却、健康、人口、视口和合法生成条件才可能启动。预警保存成功算本夜已启动；失败原计划重试，午夜未提交则取消。午夜或黎明不移除已开始的战斗。普通来袭没有经济或主线奖励。最终驻防配置单位上限4，因此计划为2—4只；沿用已有敌人配置。

夜晚到临水草坡约(1330,1470)，按E体验“临水夜风”，获得恢复药剂1瓶，整个存档一次。满包保持未领取，可整理后回来。旅馆在约(1685,1680)保留原休息服务，另有12铜币住宿，19:00至06:00前可睡到最近06:00；满状态也可住宿。未开始计划会跳过且没有战斗奖励。活跃来袭、近身威胁、未完动作、投射物或冲突提交会拒绝；保存失败不扣币、不跳时。

主线、风石顺序谜题、固定怪和宝箱不按天刷新。采集仍按累计分钟差再生；睡眠不模拟战斗，不恢复守卫、装备或伤势，不消耗有效保护/冷却。

## 模块

- data/dayNight：时段、速度、费用、光照关键帧与世界灯锚点。
- systems/worldClock：纯计算、边界、日期/夜晚编号、目标清晨。
- systems/nightDirector：单条计划、严格字段校验、启动许可与序号关联。
- rendering/dayNightView：世界坐标变换、柔边灯光、DOM分层及释放。
- systems/nightDiscovery、sleep：一致状态副本，提交前重复校验。
- systems/stateCommit、save：立即共享锁、帧尾微任务快照、串行IndexedDB事务、失败回滚；发布后重绑驻防/居民系统。

## 运行与验证

在项目目录执行npm install（已有依赖无需重复安装），npm run dev -- --port 5173，打开http://127.0.0.1:5173。正式构建npm run build，npm run preview -- --port 4173。端口已被占用时选空闲端口，不停止其他任务服务。

默认检查npm run typecheck、npm test、npm run build；新增昼夜单测已接入默认显式列表。仓库没有lint脚本。先执行npm run build -- --outDir .parry-local/day-night/production准备专项preview目录；浏览器专项可用FARWIND_URL=http://127.0.0.1:5173 npx playwright test --config tools/playwright-day-night-regression.config.ts --project 开发 tests/day-night.spec.ts tests/day-night-failure.spec.ts tests/village-raids.spec.ts。生产专项另设FARWIND_PRODUCTION_URL为已启动preview地址，选择--project 生产 tests/day-night-production.spec.ts。

完整新档旅程tests/day-night-journey.spec.ts包含正常速率耗尽5分钟保护及6分钟初始冷却，需要较长时间；不能把日历调时当作消耗有效计时。显示矩阵另开真实可见浏览器，不要同时运行另一可见浏览器以免实际失焦暂停。

开发服务器加?dayNightDebug=1显示只针对隔离存档的下一边界按钮。按钮用正式保存/校验/夜导演路径跳日历，不改战斗结果和有效保护/冷却。正式构建不包含这些按钮或可写调时全局；只读诊断返回副本。玩家正式导入只能通过严格schema校验，不能借导入缺字段重置当前档。

体验路线：新游戏→长者→药草/浆果→杂货与药师→森林战斗→黄昏预告→第一夜草坡探索→旅馆住宿→继续正常游玩耗尽保护及冷却→后续夜间村门来袭→保存继续→东北遗迹按晨风/林风/暮风顺序→快捷返回。睡眠和保存失败路线见测试报告。

## 存档和边界

原结构4经一次4→5昼夜迁移；并行居民功能继续5→6，当前结构6，地图版本仍6。旧累计时间、经济、库存、任务、采集、宝箱、固定怪、待掉落、守卫死亡和活跃来袭保留。旧档持久化首次接管夜号，从下一次符合条件黄昏接管，不补当夜。当前结构缺night/life或计划时间/序号不一致直接拒绝。保存只存时间、计划和一次领取状态，不存颜色、阶段名称或纹理。

记录与证据见PLAN、REVIEW、TEST-REPORT、STATUS及evidence/INDEX。环境音真实节点、增益、音量/暂停已验，听感工具不可用，因此不能称全部验收通过。短路线性能不等于长期60FPS或完整艺术验收。
