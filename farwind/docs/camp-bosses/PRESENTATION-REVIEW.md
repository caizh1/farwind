# 首领血条遮挡与出场修正

## 问题与修正

用户截图里的首领血条占据中央战斗区。根因是顶部弹性布局在宽度不超过一千一百像素时把首领卡片排到末行，展开小地图后，前一行变高，首领卡片随之下移。此前四百像素的验收只核对元素是否越出视口，漏掉了展开地图后的战斗遮挡，不能证明这一场景可正常游玩。

窗口改尺寸时发现另一个既有问题：入口在 FIT 模式下调用了仅适用于 NONE 模式的 scale.resize，画布保留原来的宽高比，形成大片留空。根据已安装 Phaser 源码改为 setGameSize，使画布的宽高比与新窗口一致；增加了实际画布尺寸检查。

顶部改为三个独立网格区域。宽屏首领信息与左右面板顶端对齐；窄屏首领信息先占顶部一行，旅人和地图面板在下一行。地图、任务的展开高度不会改变血条的纵向位置。名称、生命、阶段和破防状态保留，长篇技能教学从常驻卡片移除，其内容仍作为无障碍描述。所有图标及按钮继续使用正常文档流。

驻守清完后的两点五秒预警保留，随后增加一点四秒显形：孢心巢母散出孢尘，荆冠猎王伴随荆影，崩岩獠王震出岩屑，缚枝祭主卷起叶旋。首领从透明逐渐显现，脚底根保持固定；显形时不攻击、不受伤或受控，显形结束后再留六百五十毫秒准备首招，首招自身仍有完整前摇。入场时复用短促声音和轻微镜头震动，遵守玩家震动设置。

旅人有一句随首领变化的警觉短语，停步时提剑准备；移动、攻击、架剑、风步、撤战继续正常响应。警觉姿态使用玩家实际战斗朝向，不自动改方向、目标、输入或架剑成功状态，避免表现方向误导操作。

## 存档与生命周期

显形时钟与技能时钟共用战斗数据，以剩余时间保存，暂停不会继续播放，重开只继续剩余部分。没有为入场另建计时器或未托管的粒子实例。死亡与撤离释放原实例后，本轮显形和短语随同失效，重新挑战重新显形。

仍为结构十四；早期结构十四缺少显形字段时补零，已进行的战斗不补演。结构十三的历史清除迁移规则保持原有语义。入场声音仅在真正生成新挑战实例时触发，恢复存档与已有实例不重复触发。

普通敌人追击规则在验证期间出现并行修改，当前固定包已包含该修改，当前全部源码重建后的入口、脚本、样式及首领图集摘要也与实测包一致，其据点首领仍使用原活动半径；未覆盖或回退其他任务改动。最新源码重新通过相关逻辑检查。

类型检查和关闭测试授予的正式构建通过，九个相关逻辑文件共二百五十三项通过，其中首领专项四十八项；新增检查覆盖四种首领的显形攻击抑制、免伤、控制抵抗、显形中保存恢复、早期结构十四兼容和新挑战事件去重。

最终四个首领实测样本通过，无页面运行错误。共六十四个展开与视口组合中，血条高度均为六十四像素，顶部为十或二十二像素，下沿为七十四或八十六像素，与左右面板无交叠，画布均铺满对应视口。设备像素比二另验五种窗口尺寸，画布尺寸及主角可见性均通过。每位首领从新游戏出发，通过真实键鼠领取补给、购买和装备铁剑、步行及清掉驻守杂兵。仅读取诊断，不修改游戏状态。分别检查显形、旅人反应、方向输入与首招前摇；孢母还检查显形中暂停及保存重开。小地图和任务展开、折叠共四种组合，分别覆盖四百、八百二十、一千、一千二百八十像素宽度。
