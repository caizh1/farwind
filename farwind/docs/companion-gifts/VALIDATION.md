# 伙伴风赐实现与验证

日期：2026年10月3日。本轮范围为同心、递锋、并肩、递锋同行、归息，未实施全目录其他修复计划。先生成并展示[概念设计](design.png)，随后按[设计规格](DESIGN.md)实现。[生成提示词](DESIGN-PROMPT.md)记录内置图像生成工具的原始输入；概念角色不替换游戏角色。

## 实现

- 移除伙伴命中特效的默认远端连接；同心采用局部双色汇合，递锋和并肩分别显示建立及真实消费。新增消费演出只响应已成立的战斗事件，不新增攻击或伤害。
- 递锋同行分开待消费双刃结与实际附伤后的共鸣峰；目标状态优先显示当前接力阶段。消费移除对应目标尚存的建立演出。
- 刃结跟随目标，状态从真实临时标记读取；过期、死亡与清场不保留标记。归息只在真实体力增加时生成从命中点回到玩家的风团，单帧仅绘制短尾。
- 四类局部几何限制在目标60世界单位以内；归息每条短尾单轴跨度小于36。简化、降闪、同刻四演出与最多18活动风赐效果限制保留。消费峰在同刻预算内优先于普通建立。
- 教学预览使用正式绘制函数，增加建立与消费阶段；没有修改用户正式存档。

## 检查结果

1. 173项相关逻辑、美术几何、风赐、符文和闪链测试通过。覆盖正确与错误目标、3秒过期、目标死亡及移动、同行离场、连续I、三步共鸣、满体力不误播、远端距离一万世界单位仍无长线、简化与降闪。
2. 四项浏览器专项通过：两组真实I输入、实际伙伴命中、保存及刷新读档；建立与消费关键帧；全部79项教学切换及资源；四尺寸布局与暂停/释放。首轮关键帧测试使用1320毫秒，违反滑块50毫秒步进而失败；修为1300与2850毫秒后该专项通过，没有借此改变游戏时间或状态。
3. 当前工作树生产构建与类型检查通过。构建有既有大包体积提示；未据此宣称性能达标。
4. 独立来源 `127.0.0.1:5497/?windGiftArena=1` 的真实键盘I触发截图：[蓝色闪链与局部刃结](chain-and-local-knot.png)。截图来自游戏渲染器，未经修图。对应[输入证据](chain-input-evidence.json)记录2次原生命中与4次伙伴实际命中。
   同时保存[连续实战录像](gameplay.webm)，实测时长7.849秒、1920×1080。核对[开头0.15秒原始帧](opening-frame.png)，伙伴标记没有拉出玩家至敌人的长连线；蓝色电弧只发生于怪物之间。
5. 浏览器正式流程专项两组各记录2次原生命中、4次伙伴命中，分别保存[同心递锋与闪链](chain-browser-evidence.json)和[伙伴接力链](relay-browser-evidence.json)。这些实战样本未出现递锋同行附伤；完整三步附伤由逻辑测试验证，教学预览验证其表现，不能写成完整三步实战已验。

## 隔离预设问题与修复

首个新增伙伴预设使用临时敌人编号，伙伴状态记录该目标后遭严格存档校验拒绝；[原始失败样本](isolated-invalid-save.json)已保留。改为真实敌人编号后仍因挪动距离超过原活动范围、遭遇未激活而被拒绝；[第二个失败样本](isolated-range-invalid-save.json)已保留。

修复预设：伙伴组使用正式敌人编号、正式生命上限，在合法范围内站位，并在初始样本中激活相应遭遇组。保留严格校验规则，不添加例外编号、不删除伙伴战斗记录。两组实战、保存和刷新读档验证已通过。
