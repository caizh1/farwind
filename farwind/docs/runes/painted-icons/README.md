# 符文手绘图片接入

## 修正原因

用户指出参考图与实际界面差距明显。前一版本使用程序化矢量路径重绘参考方向，无法保留参考图的木纹、金属雕刻、宝石深度和羽翼笔触。前一版本的实机图保留为 [修改前截图](before-svg.png)，不把它视为本轮验收。

本轮改用内置图像生成工具，为三十枚可装备符文与固定归风制作独立透明位图。五种基准徽章依据用户提供的参考图提取，其余二十六枚沿用对应品阶边框，只更换能力主体。生成提示与来源记录见 `sources.json`。

## 正式加载

正式图片位于 `public/assets/runes/painted/`，稳定符文编号对应一个五百一十二像素的透明图片。`src/game/ui/runeIcons.ts` 直接加载这些图片；外层矢量画布仅用于承载真实图片，以及既有冷却扇面与蓄积刻度，不再重画能力主体。

图鉴、自由槽、固定归风、详情、杂货铺和战斗界面共用这一入口。所有图标位于正常文档流。图鉴显示八十八像素，详情一百四十四像素，宽屏战斗图标三十四像素，窄屏二十四像素。

| 品阶 | 直接来自图片的材质与轮廓 |
| --- | --- |
| 低阶 | 木铜圆角框，底部一叶 |
| 中阶 | 雕刻银框，顶部双卷纹 |
| 高阶 | 紫金宝石八角框，顶部三芒宝石 |
| 绝世 | 五尖金冠，白金羽翼与云纹雕花 |
| 固定归风 | 独立青玉叶片与围巾风带 |

`tools/pack-rune-icons.mjs` 只整理透明留白、尺寸与编码，完整保留绘制内容。它在生成来源清单完整且编号唯一时才输出三十一枚正式图片。图片清单与哈希在 `manifest.json` 中。

## 验证状态

类型检查、五十九项符文专项测试与生产构建通过。真实浏览器两个场景通过，合计二十五点六秒：

- 原有装备、拖拽、三套预设、品阶筛选、固定归风、刷新读档与窄屏流程通过。
- 浏览器逐枚解码全部三十一张正式图片，尺寸均为五百一十二像素，四角透明；图鉴三十枚，品阶数量为十／八／七／五，固定归风独立。
- 三十一份生产服务图片均返回成功，实际响应哈希与正式资产清单逐一一致。所有正式图标均直接加载位图，没有重新描摹能力的矢量定义。
- 使用正式装备按钮混装四品阶，再以真实攻击触发冷却；六个战斗图片均为三十四像素，两个有效冷却扇面保持显示。
- 五百九十像素屏幕的面板可视／内容宽度均为五百三十六像素；三百九十像素屏幕均为三百六十像素，无水平溢出，页面错误为零。
- 用户当前应用内浏览器已经刷新，实际装备页读取模式为手绘图片，图鉴三十个图片引用以及固定归风的正式图片路径均确认。

首次图片场景在战斗图标宽度断言处失败：四十像素容器扣除边框和内边距后，实际图片只有三十二像素。调整宽屏容器为四十二像素后，重新构建与复测通过。原始失败录像、轨迹与中文首因记录保留在 [首次运行](first-browser-attempt/result.json)，未把失败记录改写为通过。

本轮只复测图片接入相关范围；此前九百八十一项完整战斗测试是历史验收，不作为本轮重新执行的结果。完整记录见 [运行验证](runtime-validation.json)及 [源码与构建记录](validation.json)。
