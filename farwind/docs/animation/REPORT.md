# 主角与黑猫移动动画专项记录

日期：2026-09-25。范围：现有 Phaser 4.2.1 项目，未改场景、UI、任务、移动速度、角色显示尺寸或存档结构；未提交、推送、部署。当前是可运行修复增量，**动作美术专项尚未完成**。

## 证据与根因

已读取用户提供的录屏（2294×1490，约14.98秒），提取停步与连续折返画面，结合原始素材、实际加载图集、源码以及真实浏览器状态采样判断：

1. 主角侧向待机选的是原图集12／18帧；这两帧本身是跨步姿势。停止时确实进入待机帧，并非行走仍在播放。原行走每方向仅四帧，若干轮廓相似，没有足够清晰的承重和经过姿态。跑步与行走共用素材。
2. 原猫六帧均朝右，没有发现混入朝左帧的证据；其中末帧接近匍匐／扑跃，与其余帧不连续。原运行代码每次按 `dx < 0` 设置镜像，停止的零位移会重置为朝右。折返时旧路径点还可能位于玩家行进方向的反侧，猫沿旧目标运动与随后的零速镜像重置叠加，造成反向跳变。
3. 原素材脚本逐帧裁透明边，再分别按可见高度缩放；没有保留原始画布偏移。各帧比例、落地位置存在不一致风险，接触表中可见体态差异。新横向处理保留固定切格与统一尺度，显式登记锚点。原始候选源图仍存在体型差异，统一缩放本身不能把不合格姿势变成合格素材。
4. 原主角按碰撞前的输入位移选帧，撞墙仍会产生步态；原动画是世界时钟取模，不存在“每帧调用动画播放并重启”的问题。新实现不使用世界时钟取模。
5. 原猫单一距离阈值、固定追赶速度与历史目标组合，缺少减速停靠。新逻辑第一次实测也发现：玩家折返后停在猫旁，单纯近距离停止仍会长期重叠。已增加站定0.25秒后一次性选择可通行停靠点，并用回归测试覆盖。

原始代码／图集副本位于 `before`；用户视频截帧位于 `video-frames`。没有把推测的图集切错、动画重启或素材方向混入写成已确认事实。

## 必要修改

- `src/game/systems/locomotion.ts`：实际自主位移累计步态距离；朝向、状态、相位、速率分别管理；走跑阈值滞回；撞墙可面向但不行走；停步选对应待机；攻击优先；零时间步不推进。
- `src/game/entities/actor.ts`：唯一绘制／镜像入口，动作持续时保留相位；固定地面根、原点、显示尺寸和阴影位置，按地面根排序；传送使用 `place` 重置步态。
- `src/game/systems/follower.ts`：保持现有玩家路径点方案，104像素启动、76像素尾随，近距离停止，解析减速，260像素／秒追赶上限；检查视线与占地；站定重叠时选72像素可通行停靠点，不推玩家、不瞬移、不每帧切边。折返交错仍允许短暂重叠，不声称完全消除交错。视线离散采样漏过薄转角时使用按轴滑动，防止有效落点检查反复拦住同一步。
- `src/game/scenes/World.ts`：碰撞后的位移交给角色；猫使用自己的实际位移。出生／死亡重置跟随。仅开发环境开启只读动作诊断。
- `src/game/systems/interactions.ts`：已有捷径传送后同步重置角色显示根与跟随轨迹；其他交互保持。
- `src/data/animation.ts`：明确纹理、帧序列、镜像责任与临时素材标记；保留原前后与攻击资产。

## 素材结果与未完成项

通过内置图像生成制作了主角、黑猫横向候选源图，各为1254²、3×3格；固定128²输出画布，地面锚点(64,124)，0为侧向站立，1～8为行走候选。左右仅由运行时镜像负责。生成情况、原始切格、缩放和偏移在 `public/assets/animation/manifest.json` 中；不声称完成商业权利审查。

已接入并录制实际运行。侧向站立、猫同向连续性比原版明确；但检查连续放大画面后，仍可见部分姿势重复、手臂与腿部配合不足，主角局部比例有变化。因此，**八张候选不等于八个合格关键姿态，完整步态美术未验收**。

- 主角前后方向保留原四帧行走和待机，未完成新步态。
- 猫前后方向仍缺独立素材，继续沿用侧面，不标成四方向完成。
- 两者奔跑状态已按速度选择，但没有专用奔跑资产，目前复用行走，未完成奔跑美术。
- 没有靠降低移动速度、缩小角色、模糊或整图上下抖动掩盖素材问题。

下一步最小素材任务：先精修右向8个有效关键姿态（左右接触、承重、经过、摆动），修正主角手脚协同及猫四足支撑；以现有角色源图锁定体型。交付128²透明帧、统一(64,124)地面锚点；有透明裁切时附原始128²与偏移。主角显示86×92、猫55×54保持。先在固定预览与地面移动两处通过，再制作前后行走及奔跑。不能用重复帧或整图变换补数量。

## 如何复核

在项目目录运行 `npm run dev`，打开 http://127.0.0.1:5173/ 。开发诊断使用 `/?animationDebug=1`；默认游戏关闭。`/animation-preview.html` 是固定地面根的三倍放大预览，可选择角色、方向、动作与暂停；使用实际 Actor 和 Locomotion。加 `?baseline=1` 为旧公式预览。该页面不进入生产构建。

接触表：`before/hero-contact.png`、`before/cat-contact.png`、`after/hero-contact.png`、`after/cat-contact.png`。实际帧映射与缺项在对应 `animation-mapping.json`。生成脚本 `tools/prepare-motion.mjs`，更新接触表 `node tools/after-contact.mjs`。

正常速度实际游戏对照：`before/same-route.webm`、`after/same-route.webm`，1280×720，有头 Chrome，相同按键时间路线；不修改位置或状态。折返、停止、上下短移、奔跑均包含。版本校验、路线、浏览器版本与约50毫秒只读采样在 `route-record.json`。相同输入路线不意味着每帧坐标完全相同。

固定放大循环：对应目录 `hero-loop.webm`、`cat-loop.webm`，属于开发预览，**不冒充实际游戏录屏**。修复后记录的源码／纹理校验见 `after/loop-version.json`。

调试矩形为24×20地面占地参考，与建筑占地判定中的水平12／垂直10像素扩张一致；不是动画可见包围盒。放大预览同步放大为72×60。
