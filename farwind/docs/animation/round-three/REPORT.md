# 角色动作与会话状态收尾

日期：2026-09-25。基于 codex/initial-game、HEAD 4c552c3afeae21902fcc4b7dda318ed41b273f95 的当前工作树。已有 favicon 改动保留；本轮未提交、推送或部署。完整基线及中间失败见 [BASELINE.md](BASELINE.md)。

## 逻辑修复

FW-01 在当前代码确实存在：World 每帧仅以体力大于1判断奔跑，消耗后立即恢复并反复跨过同一个门槛。修复前真实输入录像的300次采样中有130次动作切换。新增移动层 Sprint 锁存耗尽状态，1点耗尽、20点恢复，持续按住或反复按放Shift都不能绕过恢复区间。正常速度150／235、消耗21／秒、恢复14／秒不变。20是本轮起始值，并非已证最优手感。

FW-02 在当前代码同样存在：start重置sim但遗漏attackUntil；攻击和采集都写入这个截止时间。新会话统一重置sim、attackUntil、cooldown、invulnerable，同时清键并恢复主角显示透明度；Actor.place沿用原有动作重置。敌人重建会重置各自计时，不增加无关字段清零。普通暂停不调用重置函数。背包、任务、机关、世界时间和音量设置不受影响。

新游戏、继续与死亡回安全点都会按当前体力重建耗尽状态；读档体力低于20时保守进入恢复态，避免继承上一段旅途的锁存历史。碰撞后零位移仍由Locomotion判为idle，没有以想跑状态强行播放跑步。

修复后相同开场路线采样只有10次跨完整恢复区间的正常走跑切换；恢复后采样可能已因当帧消耗显示小于20，但重新允许的判断使用消耗前体力。攻击自然结束后同页继续，实测动作walk、attackUntil为0。

## 动作素材与运动

- 新增仅四组竖向跑步：主角上下各8帧，猫向下8帧、向上6帧。猫背面两个腿序不合格的候选剔除，没有重复帧凑数。
- 主角51、猫49个有效帧，图集均1024×896；帧128×128、根(64,124)，显示尺寸仍86×92与55×54。原0—34帧由原始RGBA回填并逐像素校验，已可用的侧向动作、行走和待机保留。
- 内置imagegen生成并补画；源图、制作约束、修订记录、切格、每张源图固定缩放与锚点均保留在 public/assets/animation/round-three。没有旋转侧面、复制行走或逐帧包围盒拉伸。生成素材商业权利尚未审查。
- 竖向跑步循环距离主角110、猫72逻辑像素；侧向142／108、行走96／76保持。由实际位移累计相位，未添加第二个动画计时器或改变移动速度。角色腾空由素材表现，地面根、阴影与碰撞不随之漂移。
- 正常攻击与采集仍使用既有素材和定时，检查了切换与恢复；本轮未改伤害、冷却、范围、奖励或新增连招。跟随算法没有修改。

固定根预览和实际游戏均独立录制并检查。观察到上下跑步腿部交替、稳定朝向与比例，停步恢复原自然待机；没有发现需要重写跟随或重制攻击库的明显错误。仍有相邻姿势接近、猫背面细节较少的手绘精修空间，不宣称专业逐像素足底锁定，也不登记用户美术验收通过。
