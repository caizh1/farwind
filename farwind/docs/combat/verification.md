# 战斗机制一期验证报告

## 版本与基线

本轮从 `bc6458d8fc06d809c1bd5a2862a1ccee117df434` 开始，初始工作树干净。实际依赖为 Phaser 4.2.1、TypeScript 7.0.2、Vite 8.3.1。旧攻击在按下瞬间扣血、无输入缓冲、单姿势显示；敌人受击闪色会被同帧更新清除；满包会把致死敌人恢复到 1 HP；采集复用了攻击显示截止时间。五条旧线索在当前代码中均成立，现已替换。

目标用户为用键盘或鼠标操作二维俯视游戏的玩家。输入限定为既有移动、奔跑、交互、菜单和新增的 J／左键普攻、Space 风步。支持现有史莱姆与叶灵，不扩展新敌人、地图或其他技能。质量门槛是单次输入只出一刀、三段按节奏衔接、有效期内且不隔墙命中、同实例同目标只扣一次、暂停及续玩无旧攻击、满包无任务物品丢失。没有对人工操作节省 80% 的独立量化基准，本报告不作该项达标宣称。

## 实现与证据

| 项目 | 当前结果 |
| --- | --- |
| 普攻 | 三段分别配置前摇、有效期、后摇、范围、角度、踏步、伤害、击退、闪色、硬直和姿势；150 毫秒单请求缓冲，末 100 毫秒衔接窗口，结束后 200 毫秒宽限。 |
| 风步 | 90 逻辑像素、200 毫秒位移、20 体力、650 毫秒冷却，40～140 毫秒独立无敌；受控子步碰撞，成功启动才扣费；攻击仅在规定收招窗口可取消。 |
| 敌人及掉落 | 轻击短闪色与短硬直，第三段可中断普通前摇并受控击退；死亡只结算一次。满包时在敌人原位置保留可领取记录，旧档缺省迁移。 |
| 素材 | 新战斗源图经内置图像生成工具生成，按“红围巾旅人、三视角、三种不同挥击、透明背景、维持原体型与脚底锚点”的提示制作；运行图集为九格，原走跑图集未改。前摇与收招从既有角色姿势取帧，有效期使用新图集。 |
| 开发诊断 | 仅开发环境显示阶段、段号、实例号、锁定面向、命中区域、已命中目标、缓冲、冷却、无敌来源及敌人状态。 |

逻辑测试：`npm run test`，31 项通过，包含跨阶段大步长、去重、连段过期、方向锁定、取消窗口、碰撞、30／60／120 Hz 固定目标结果、闪色优先级、旧档及满包往返。类型检查 `npm run typecheck` 通过；`npm run build` 通过。

浏览器测试：`npm run test:e2e`，10 项通过。原主线用实际键鼠从村庄走到森林、遗迹、捷径和奖励，再保存续玩；独立森林战斗夹具用实际按键完成三段命中、风步拉开和补刀；满包夹具只预置单个叶灵及满背包，实际击杀、整理、按 E 领取并验证续玩后不重复。旧行走、奔跑、黑猫跟随、体力滞回、会话重置、输入隔离、暂停、背包和任务回归通过。另在浏览器手动继续存档并按 J 检查了当前画面。夹具直接设置的前置状态不计作主线游玩证据。

正常速度运行录屏：[完整森林与任务闭环](regression/forest-quest.webm)、[森林三连与风步](regression/forest-combo-dash.webm)、[同段动作裁切特写](regression/forest-combo-closeup.webm)、[输入节奏与暂停续玩](regression/combo-input.webm)。裁切特写只放大当前录屏，没有改变播放速度。对应截图位于 `regression/`，旧 `docs/animation/round-three/regression/` 证据保留。

## 审查结论

VERDICT: PASS

P0/P1 BLOCKERS: 无。已反证检查攻击回调和实例生命周期、满包死亡事务、存档迁移与重复奖励、碰撞路径、暂停／失焦、受击闪色优先级、按键重复以及风步和受击保护并存；没有发现满足可达性、严重影响与证据要求的阻塞问题。

UNVERIFIED RISKS: 用户尚未对新战斗素材做正式美术验收；未在目标机器上测量稳定帧率，不能宣称 FPS 达标；长期平衡与更多浏览器组合尚未量化。

NON-BLOCKING FINDINGS: 本轮未加入短促 hit stop，优先保证结算稳定；构建仍提示 Phaser 主包超过 500 KB，这是体积提示，不影响构建或现有流程。
