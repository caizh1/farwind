# 卫兵原地打转修复（2026-09-28）

本轮针对用户录屏中的东门青禾返岗打转。复现起点为村庄坐标约（2020.54，953.72），真实岗位为（2010，1160），岑风仍站在（2010，970）。未移动岑风、取消碰撞或把青禾直接设为在岗。

## 首因与修复前证据

生活寻路原来只把地图和安全区域交给规划器，同伴占位仅在实际走步时检查。旧缓存首个路点（2020，960）进入岑风的十八像素占位范围，青禾被挡后做一小步切向侧让，下一帧又走回原路点。每次侧让把卡住计时清零，因此没有真正前进也被当成成功移动。

返岗卫兵已经没有生活行动；生活决策在返岗分支直接返回，普通行动的八秒失败处理也不会替它解决这条路线。这是本次持续打转的直接原因，不能把它等同于游戏中所有渲染长帧。

[修复前同路线对照](evidence/guard-return-before.json)记录四十个模拟秒后仍未到岗，距离岗位约二百零六像素，卡住计时始终为零。只在离线诊断中移除站岗者占位后约二点四七秒到达，说明阻塞来自局部同伴避让。游戏里的站岗者没有被移除。[卡住存档](evidence/guard-return-save.json)来自修复前真实规则模拟，可通过正式导入按钮复现。

## 实际改动

同空间人物的位置作为临时占位快照参与已有分步寻路，同时检查整段移动是否穿入同伴占位圈。动态占位不写入静态地图缓存；室内同坐标不会阻挡室外。后来进入缓存路线的同伴会使对应路段失效，并在原共享预算中重新规划。

取消了撞到旧路点后逐帧交替侧让的处理。共用房门已经存在的重叠仍可逐步分离，每一步继续满足地图碰撞和安全规则。进展改为从上次锚点净移动至少十二像素，细小来回摆动不会不断清零卡住计时。重新规划间隔仍为一点八秒，每批最多六十四节点，单次搜索最多八千一百九十二节点。

返岗同样经过共享移动入口。实际通路未恢复时保持安全等待和有预算的重新规划，超过八秒后给出明确原因；不会把等待者标为在岗，也不会补血、复活或瞬移。普通生活行动沿用已有八秒取消、释放预约和备用安排。

追加多日检查发现三座城门的弓卫原来共用临水长椅前的同一个目标。加入真实占位后可能互相等待并取消休息。现分配（1540，1390）、（1504，1390）、（1576，1390）三个可站立落脚点，间隔三十六像素。旧档进行中的同名习惯也会比较地点并重新评估，不能用旧目标覆盖更新后的个人日程。

## 状态与存档

卫兵位置、生命、死亡和战斗结果仍唯一归驻防状态；生活系统仅提供非战斗目标和共享移动。未修改驻防伤害、射界、轮休最低人数、塔位及召回规则。守卫的归岗状态仍需实际抵达后由驻防确认。

当前工作树主存档为七，生活子版本为四，本轮没有增加存档字段、改迁移链或改变二十万字符限制。新增进展锚点只属于临时导航对象，读档后重新建立；在途身体和已经提交的项目、资源及经历继续保留。无需开启新档或删除旧档。

## 验证方式与边界

固定回归先确认旧代码无法到岗，再验证绕过岑风、失效缓存路线、同伴后来占路、跨空间隔离、三门午休后返岗、三弓卫临水休息与旧目标读档恢复。返岗模拟同时使用六十分之一秒和一百毫秒步长，速度、碰撞、实际岗位与寻路预算断言均保留。

浏览器使用正式存档导入、暂停菜单保存及继续旅途，没有运行时位置或生命注入。录屏对应的原位置恢复案例还检查暂停冻结、返岗中途读档、站岗者不动和每门至少两名可用守卫。[返岗采样](evidence/guard-return-browser.json)、[实际到岗截图](evidence/guard-return-arrived.png)和[录像](evidence/guard-return.webm)保留。

夜间浏览器案例从真实日程模拟生成的二十一点存档开始，三人正常走出营房、分别临水休息。返岗检查使用两次公开开发全世界快进，明确区别于实时等待；快进同时推进移动、战斗与生活。完整命令、首次失败、最终结果及多日记录见[测试报告](TEST-REPORT.md)。

首次完整浏览器批次的旧配药救援脚本曾在玩家持续行走受击时超时。失能和暂停读档此前已通过；现场生命十、显示受击恢复中。仅使用修复前寻路进行对照及当前实现单独补验均通过，未删除或放宽任何旧断言，原追踪保存在本地首次失败目录。这类固定键盘路线的时序敏感仍保留为验证风险，不能声称已经找出了全部浏览器波动原因。

真正被堵住的入口仍可能等待或取消生活安排；本轮没有允许穿人、穿墙或绕过安全约束。未穷尽所有多人拥堵组合，短样本和软件图形浏览器不能证明目标设备稳定六十帧。
