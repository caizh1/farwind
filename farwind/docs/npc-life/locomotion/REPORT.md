# NPC 行走动画补齐与滑步修复

二〇二六年十月一日追加了近战卫兵左右脚交替步相；下文保留此前阶段的检查记录，最新结果见 [卫兵脚步复查](guard-step-followup.md)。

四门弓手以及岚爷爷、小满、阿禾已接入真实六帧行走；近战卫兵改用整帧实际位移判断行走，避免时间轴末尾的小片段没有移动时短暂站姿滑行。游戏位置仍由原有寻路和战斗逻辑推进，表现层只读取位移。

## 原因与覆盖范围

录像中的远翎是西门弓手。原先只有近战卫兵进入行走姿态；弓手轮休时坐标会回家，画面却继续使用塔上的站立射箭素材，方向也没有跟随地面移动。

| 对象 | 检查结果与处理 |
| --- | --- |
| 弦雨、林弦、晴羽、远翎 | 补齐正面、背面、侧面的站立加六帧行走，左向由角色镜像；实际移动时切换地面图集 |
| 岚爷爷、小满、阿禾 | 原来移动时只切换站立眨眼帧；补齐同样的方向步态 |
| 八名近战卫兵 | 已有方向及两帧迈步；修复末尾小片段的零位移掩盖整帧移动的问题 |
| 小宝、小黑 | 已有真实位移驱动的独立步态；未发现同类缺帧问题 |
| 固定商人、建筑及交互摆件 | 没有自主移动，不存在这条滑步路径 |

新图集每套三行七列，共二十一帧，尺寸为一千一百二十乘四百八十；一百六十方格，脚底根固定在八十、一百四十八。仅切分、等比缩放、对齐生成姿态，不复制站立帧伪造行走。步态按累计实际路程推进，停步立即站稳，暂停不推进；进入房屋、上下塔、读档重建和纠正站位不会累计假步幅。

## 验证结果

相关逻辑与素材测试共一百四十九项通过，覆盖行走帧率、暂停、转向、传送、受伤、生活寻路、轮休、昼夜、守备和职业动作。四套图集均有二十一张独立帧、真实透明边缘及固定脚底。类型检查和正式构建通过，差异格式检查通过。

浏览器共七个场景通过：开发环境两个、正式构建两个，以及职业四帧、睡眠裁切、近战转弯三项回归。所有通过场景均通过界面操作并只读采样，不改写浏览器运行状态。

居民场景从真实新游戏开始，由自然生活决策取物。弓手场景导入明确标记的合法固定样本：首日晚间四名弓手落地、有完整轮休任务，南门最近的芦边史莱姆已击败且尚未重生。此样本用于验证地面回家表现，不作为自然触发全部轮休的证据。四人暂停时状态和画面冻结，保存、刷新、继续后坐标连续；远翎读档后另有五十九个行走样本，页面错误为空。

固定构建前记录三百五十二个输入文件摘要；构建期间无输入漂移，四套图集在源码与构建中完全一致。摘要见 `evidence/build-inputs.json` 和 `evidence/build-consistency.json`。

早期失败已保留首因：缺少轮休任务的样本会走返岗及塔楼过渡，短暂观察没有实际移动；南门最近怪物距塔岗约三百一十六，低于三百二十的警戒半径，会正常召回晴羽。补全合法样本后四名弓手均通过。既有近战回归首次失败仅因读档后剩余八点四三的斜向路程只有六个采样，朝向和随后的下向转弯均正确；取消与帧率有关的十帧门槛，保留逐样本朝向、暂停、存读档距离和实际转弯检查，最终通过。详情见 `evidence/archers-first-failure.json`、`evidence/guard-facing-first-failure.json`。
