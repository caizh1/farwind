# 小宝的自主生活与护村

小宝沿用现有小宗师控制器管理生命、真气、坐标、空间和战斗。居民生活系统管理需求、朋友、记忆、设施预约和完成凭据；新的生活决策只提交行动意图。日常移动和护村移动均由同一控制器执行，室内人物不进入室外战斗名单。

每天按持久化种子选择主要和可选心愿。饥饿、疲劳、已开始的活动及同行承诺优先；动作完成前不会因为随机喜好反复换目标。生活范围为受保护的村庄和安全近郊、可用室内，不主动清剿据点或推进玩家主线。

三项长期心愿各有三个阶段，必须在三个不同游戏日与实际在场的对应朋友完成学习。木鸟需要先实际到工坊取木料，完成最后阶段才消耗；药草必须采好后提篮到场交给药师。住处收纳界面展示已经完成的风向本、木鸟和辨药记录，日记保存亲历过程。

正式来袭、确认入侵和村民或设施遭攻击抢占生活、演武、等候、随行与战斗指令，最长决策间隔为150毫秒。未释放的冲突攻击取消，已释放攻击继续结算。室内先实际走出房门，随后按原有落点检查、航程和冷却飞援，不能飞援则沿路赶赴。危机期间驻防范围与旧关闭回援状态均不能阻止护村。持续安全十秒后处理目击伤情和材料帮助，再恢复仍有效的委托。

邀请允许接受、稍后同行与婉拒。重复点击沿用同一有效答复，承诺最多一个游戏小时；危机取消待兑现承诺，过期需要重新确认。预约、库存、学习进度与关系只在实际完成后更新，中断保留明确退出原因。

战后探望依据亲历或听到的伤情，涵盖守卫与普通居民；在疲劳未超过原阈值时优先于夜间睡觉。已完成探望且没有维修事实，就恢复仍有效的直接接受或已经兑现的稍后同行；危机中重新选择自由生活或巡护，会撤销此前的恢复意图。

保存增加小宝生活记录，保留结构20到21的纯迁移逻辑。根据用户后续决定，正式入口使用战斗第二版的新旅途，不继续旧档。当前源码与最终长测候选包使用结构21，以内容版本2区分新战斗内容。早期结构22候选仅保留为修复过程证据，不计入最终连续长测。保存仍通过原有串行队列和原子事务，失败保留上一份有效档。暂停、后台、保存冻结不推进模拟；住宿跳时只更新当天安排，不补发生活成果。

HUD可查看小宝的今日心愿、打算、日记和上次见到的位置；面对面才可商量同行与演武。图标和按钮保持正常文档流。新增吃饭、采药、提篮和笔记素材共24帧，保留临时美术标记，固定预览与真实移动证据分别验收。
