# 缚枝祭主 Blender 动作样片

本轮目标是验证三维骨骼能否改善东侧首领的迈步、腰肩发力和双镰衔接。交付范围为离线动作样片；未接入正式战斗，没有更改游戏存档、伤害或招式配置。

## 工程与动作

- 使用本机 Blender 5.2.2 LTS 和 EEVEE 渲染。
- 创建实体树束、双镰、面具、风核、根趾及分层枝叶，共二十一根骨骼、一万五千九百三十四个网格顶点。
- 模型、绑定、控制器、材质、相机和逐帧动作保存在 `source/east-boss-motion.blend`，使用的图片已打包。
- 六秒动作依次为警戒、转身迈步、第一镰蓄力与出手、借势换手、第二镰出手、收势、风核暴露和恢复。
- 肩腕之间采用双节关节求解；肘部极向根据肩腕轴法向生成，避免极向共线。枝叶相对于身体转动有延迟。

## 原版对照依据

`tools/export-east-boss-baseline.mjs` 直接调用当前游戏中的 `BossMotion`、`deformBossPoint`、`createBossAttack`，按每秒六十帧采样。原版沿用二十乘二十的网格和主体高度四百八十像素的正式纹理。

这份对照是原版角色本体的算法重建，不是实战录像；不包含攻击特效、危险区、伤害或玩家操作。两侧在 Blender 中使用同一地面与相机，原版角色按新模型第一帧的实际投影上下缘匹配大小；共同使用同一输出色彩管理。详细参数见 `evidence/baseline-match.json`，源码摘要见 `source/baseline-provenance.json`。

## 美术与性能边界

当前三维造型保留了原版树灵、面具、双镰与风核识别点，但树皮、叶片、面具和镰刃的精细绘画质感仍弱于原画。它属于可检查骨骼、脚步与连续发力的动作样片，尚未达到正式美术替换标准。

正常样片为每秒六十帧的离线渲染。视频流畅不能证明正式游戏帧率。正式战斗中的预警可读性、碰撞、命中、招架、保存恢复以及设备性能均未在本轮验证。

以每帧七百六十八乘一千零二十四像素、四通道、三百六十帧计算，单方向未压缩纹理约一千零八十 MiB，八方向约八点四四 GiB，尚未计入图集留白。当前首领的解码预算为一百九十二 MiB。因此正式接入前需要动作裁切、帧复用和按需加载设计，不能把全部高清帧直接装入当前图集。

## 复现方式

在项目根目录执行：

```sh
node tools/export-east-boss-baseline.mjs
/Applications/Blender.app/Contents/MacOS/Blender --background --factory-startup --python-exit-code 1 --python tools/build-east-boss-sample.py
/Applications/Blender.app/Contents/MacOS/Blender --background --python-exit-code 1 --python tools/check-east-boss-sample.py
```

随后分别使用 `--load --render main`、`--load --render side`、`--load --render baseline`、`--load --render detail` 调用构建脚本，最后运行 `python3 tools/compose-east-boss-sample.py`。渲染中间帧位于 `.east-boss-motion-local`，不会进入版本库。
