# M3东门防御审查

VERDICT: PASS

## P0/P1 BLOCKERS

无。审查范围为本轮东门受控防御切片；这不是整份M4/M5计划的批准，也不代表候选美术验收。

## 已检查的因果链与反证

- 保存：实际怪物接触使守卫HP达到0，取消攻击、路径和该射手箭矢，仅产生一次死亡；世界末尾复制完整状态并串行保存。IndexedDB按事务完成判断成功。请求成功后事务中止的实机故障注入已复现：旧有效档仍是HP1、未阵亡，运行态保持阵亡并暂停提示；关闭故障后手动保存、重载仍为0和阵亡。不存在“单次写请求成功就批准死亡保存”的路径。
- 时序：所有驻防与来袭进入玩家同一个有效模拟时钟。菜单、失焦和暂停重置墙钟映射，同时停止双方；恢复不补离线时间。自治攻击不调用玩家全局停顿。成功的关键后台保存不清除持续输入；持有左行按键且远处结算的实机路径已验证。
- 交易交叉：交易提交状态副本后仅重新绑定驻防状态，不重建正在运行的攻击或箭矢；商店暂停世界。保存队列按调用快照串行，失败不阻断后续保存。不把动态敌人结算塞进固定任务、背包或掉落表。
- 动态目标：玩家近战和新剑风都走驻防敌人的独立分支，共用阵营伤害与正式装备增伤；不会落入训练靶的sync调用。实际四连剑风对来袭怪扣36HP，K弹反正式接触成功；守卫不进入玩家攻击目标集合。门内的来袭怪可伤玩家，取消其旧村内无敌条件，固定野怪仍保持本阶段原区域行为。
- 箭矢：来源是有HP、岗位与装备的弓手；死亡或离岗不生成箭。飞行按连续线段检查，高屋顶和实体门柱阻挡，仅登记的本塔射击口可越过指定己方低围挡和自己的塔身。每支箭命中后清理，恢复存档不重放未保存箭矢伤害。
- 导航与生命周期：共享每帧查询预算及现有局部寻路，不进行全图逐帧搜索；位移使用正式碰撞连续查询，拦截受岗位追击半径约束。射手不占门洞地面；塔基阻挡、门洞和旧村门柱通行检查保留。事件最多4个成员、12支箭、120秒；结束清空实例，序号和完成序号防重复恢复。
- 数据：旧结构2到3只初始化首次驻防；结构3缺失或不一致的死亡字段拒绝，不补满血。地图4到5不平移；旧+600仍只在未迁移的旧地图执行一次。保留本轮共享快照已有的剑风学习字段，不用M3覆盖其新增字段。

每项候选问题均核对过调用约束、已有保护、实际触发路径和影响程度。没有发现满足当前范围P0/P1六项条件的阻塞问题。

## UNVERIFIED RISKS

- 三项B类弹反画面识别用例在本轮扩展回归中失败。两个实际输入晚于首次接触约23毫秒；另一个正常弹反成功，但短暂HUD“成功”提示未被轮询看到。首因、截图和追踪保留；A类五项键鼠功能回归通过。没有修改窗口使这组失败变成通过，B类画面验收仍未关闭。
- 新守卫、弓手和木塔仍为候选。生成素材的完整动作一致性、角色身体大小、低栏遮挡、弓口对齐和木塔屋顶需要人工确认；截图保存不等于批准。
- 没有目标设备长时间内存／帧时间实测，不宣称60FPS；没有30波平衡试验，不宣称守卫连续30波无死亡。
- M3箭塔射手在高台上不被地面近战选作可达目标。HP、致死和塔停火接口是真实的；实机的实际怪物致死样本是近战守卫，弓手死亡使用合法历史存档和逻辑受控伤害验证。
- 关键保存失败后若用户忽略暂停提示强制关闭，尚未成功提交的死亡不能保证落盘；旧有效档保留，已提供重存与导出入口。

## NON-BLOCKING FINDINGS

- M3驻防仅针对本轮独立来袭实例；常驻野怪、三门复制、定时骚扰、30波平衡与正式防守奖励留给M4/M5。正常生产版不暴露开发启动按钮。
- 两名近战通过统一脚点及自主位移驱动步态；镜像统一交给Actor。候选角色在部分前景围栏之后的姓名可被遮挡，人工视觉检查需评估可读性。
- 新增源PNG解码增量约18.9MB，不包含驱动副本或浏览器缓存；已有构建大块警告仍存在。这是容量估算，不是性能测量。
