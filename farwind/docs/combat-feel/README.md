已复现的三个疑点：

1. 击杀调用原 `persist → StateCommit.run`，`busy` 会让 `World.update` 冻结模拟、排空输入、重置时间线。普通自动快照改为更新结束后捕获并排入原存储路径，不锁战斗。
2. 原风步期间攻击直接返回；原第三刀拒绝全部风步取消。现在只有有限尾部窗口可预约，合法点实际发动时才扣体力。
3. 原普通硬直推迟攻击时刻，并不取消攻击。现在强敌轻微受创保留来招姿态；真正打断只取消未释放实例，破防给出真实可利用的恢复窗口。

## 实际基线调用链

- 输入：唯一 `Input` 监听按下/松开，重复按住不重复预约；使用单调浏览器墙钟记录 `J/K/L` 和方向。`World.update → CombatTimeline.frame` 按序映射到模拟子步，再进入 `requestActions → flushActions/CombatController.update`。原时间线每帧模拟预算最多 50ms、子步 5ms；慢帧的真实墙钟仍另行保留。起手方向属于攻击实例，移动意图与表现面向分开，不中途旋转一刀追踪。
- 清理：原受击、取消、重开、暂停、失焦、事务忙碌会清输入。原普通击杀也进入事务忙碌，因此触发 `drain/reset`；本轮只将普通快照移出该锁。真正需要发布新状态的事务继续冻结。未释放剑风取消可阻止发射；合法释放后的实例独立存在。
- 原普通接触：`tickAttack → strikeTarget → strikeEnemy/defense.damageEnemy → resolveDamage`，先正式扣血，再闪白、数字、受创、停顿和声音。原野怪击退为直接坐标改变后校验，驻防反应路径与其不同。第三刀普通接触曾使用终结声音；本轮改为按正式结果区分重击与致死。
- 死亡和保存：`recordEnemyDefeat` 负责既有持久死亡、唯一掉落与进度；驻防死亡通过正式通知进入同一记录。原 `persist → StateCommit.run → save → publish` 会暂停模拟、动画和输入。本轮死亡事实不等待演出，有限死亡表现沿用原素材与视图。
- 全部锁调用者：交易/住宿、存档导入、伙伴任务、恶意初见、夜袭预警、夜风发现、驻防演练、委托、南部任务、剑风学习、换区和捷径维修均已追踪；这些原子提交继续保留锁与串行写入。

基线的木桩、四种单怪、群战、真实树障、剑风开/关和正常速度结果保留在 `demo/baseline-initial`、`demo/baseline-complete`。原源码仅为隔离对照副本，不在正式游戏中长期维护第二套控制器或旧存档实现。

反应曲线集中在 `enemyReaction.ts`：轻击 90ms、重击 125ms，剩余位移合并后限幅 36px，逻辑根受真实碰撞约束；视觉小幅后坐独立。真正打断恢复至少 420ms，史莱姆轻击打断恢复至少 240ms，原有更长冷却不会缩短。守卫破防 900→1200ms，窗口内再次重击不续满破防。命中停顿仍 36/36/58ms，同一攻击多目标仅请求一次，不逐个续满。

近场许可集中在 `encounterTempo.ts`：340px 内，主要出手最多一近战加一孢卫。基线实测会同时有两近战加一远程。许可从活的正式攻击推导，取消、死亡、恢复、换目标、离开范围即释放，没有独立占用锁；等待者仍移动绕侧。它只作用于面向玩家的新起手，不限制小宝/守卫目标和远处驻防，也不撤销已承诺攻击或已发射弹体。

140ms、110ms、1200ms、一近战加一远程是技术验证后的调参候选，尚未获玩家主观认可。没有新增朝向辅助；保持键盘方向、起手锁向和原判定。

## 保存契约与失败行为

- `SaveQueue` 共用串行 FIFO。自动快照在同步更新结束后的微任务边界由 `validate` 捕获独立副本；只合并尚未开始、队尾、同会话的自动请求。合并调用者等待同一个真实写入结果。关键显式保存不合并。
- 活世界变化递增版本，不产生复制。旧写入只确认它捕获的版本；新变化即使还没请求快照也保持未保存。完成回调只更新持久化副本及同版本确认，不将旧快照发布到运行世界。
- 交易、住宿、导入、夜袭预警和明确成功确认的关键流程保留 `StateCommit` 原子锁。事务与自动快照进入同一 FIFO；事务开始失效旧自动回调，避免旧确认覆盖交易结果。
- 会话切换先禁用活动与输入，失效排队旧请求，再等已开始的真实 IDB 写入结束，之后才重建会话；新游戏初次保存也受初始化入口门禁。不是只忽略回调。
- 普通周期快照每 5000ms **模拟时间**请求，击杀等已有关键变化立即请求。强制关闭可能损失最后一个周期和存储延迟中的变化，不能保证异步写入必定完成。正常“保存并返回标题”先等显式保存。
- 写入失败发生在原子 IDB 事务中，不先删除旧有效档；内存状态保留。提示最多每 4 秒一次。普通驻防/死亡检查点保留待保存标记并在 5 秒墙钟后重试，或由周期/新变化/显式保存再请求；无无界重试。关键事务失败不发布新副本，保留原错误/暂停策略。
- 队列最多 8 个等待作业加 1 个运行作业；满时明确失败。输入、反馈、画面和声音不再次扣血、掉落或推进任务。

## 验证与边界

具体命令、失败归因、性能数值和录像索引见 [VALIDATION.md](VALIDATION.md)。没有复制参考游戏资产，也没有按印象引用其具体实现；复用现有角色/敌人/死亡素材及程序合成声音，没有依赖升级。

最终实录在 `demo/baseline-complete/normal-speed.mp4` 与 `demo/candidate-complete/normal-speed.mp4`，带真实游戏音轨。十分钟候选检查为 600.095 秒、56 轮重置、133 次正式击杀、页面错误 0；软件渲染长帧较多，目标设备帧率未验收。定向逻辑 188 项通过；开发专项累计覆盖 12 项、正式构建完整世界累计覆盖 4 项，包含真实商店交易、暂停和刷新；没有将分次通过写成一次整轮全绿。全量逻辑 771/781，10 项超时，详细归因范围见验证记录。

常规全量浏览器最终为 88 通过、137 失败、2 跳过，194.26 分钟，**未全绿**。其中 89 项未完成首因归因，另有 4 项原版同用例也失败但当前首因仍未归因；不能统称旧测试问题。137 项索引为 `demo/validation/regression-summary.json`。本轮自动生成的 84 个非英文证据路径已改为英文，原始日志/结果保留，附件映射为 `demo/validation/english-path-map.json`；没有删除或重新打包大证据。

新增动作诊断的采集合法字段漏含空弹恢复锁，也可能早于迟到请求；实际权限和执行保留原规则。`demo/comparison-final.json` 保留原字段，按正式架剑起手及 320ms 恢复校正，两次较长群战等待均属于真实空弹恢复。不能直接用原字段计算额外延迟。程序重置后的下拉框文字仍保持用户上一次选择，输出标签记录实际样板；手动选择后重置的路径正常。

需要玩家亲自判断：输入窗口是否舒服、弱怪与强敌的承诺是否合适、护甲/破防/击杀是否容易辨认、群战是否过于克制、音色和响度是否满意。自动化、正常速度画面和软件渲染性能各有范围，不能登记最终“已经好玩”或真实设备听感通过。
